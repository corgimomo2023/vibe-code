## Environment

- Reviewed revision: Working tree; repository has no accessible Git metadata in this environment.
- OS/runtime/dependencies: macOS, Node 20.14, npm 10.7, Docker Compose, PostgreSQL 16, Python 3.12.12, uv.

## Known limitations

- The local seeded named-user identity path is the only login path in this POC; SSO/OIDC and AI gateway integration are intentionally excluded.
- The Coder REST adapter uses member-scoped workspace creation, per-user Coder owner mappings, exactly one template ID or template version, provider-reflected readiness/lifecycle, and runtime-only Git secret inputs. Live workspace provisioning, code-server proxying, Git remote recovery, and Kubernetes operations still require operator credentials/infrastructure.
- The local Compose adapter provisions the source and persistent data, while the `workspace-ide` service exposes a real code-server browser IDE against the same volume. The Coder/Kubernetes template remains the external one-workspace-per-project deployment path.
- Local code-server authentication is disabled so the browser IDE can be opened directly after the local named-user flow; this is suitable only for a developer's local machine. It is not an ownership boundary for shared or production access, where the Coder authenticated proxy is required.
- The local provider intentionally keeps the generated FastAPI app source, SQLite file, and Git commit in a Compose volume; it does not claim cluster isolation.
- Local workspace recovery can reseed a missing source tree from the golden template and rebuild its Git snapshot; this protects the local POC from an inconsistent persisted fixture but does not replace external Git-provider recovery.
- TypeORM synchronization is local-only; migrations are required for a shared environment.
